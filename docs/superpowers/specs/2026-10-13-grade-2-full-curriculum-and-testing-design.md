# 二年级全学期课程与质量保障设计

> 状态：根据用户要求，对本规格和实施计划分别完成两轮严格审查并修复发现的问题；以下为当前实施依据。

## 目标与范围

将二年级上、下学期的语文、数学和英语课程做成可玩的互动学习任务，按年级、学期、学科、单元、难度、任务和场次组织。每个单元的基础版拆成多个小任务（至少 2 个，按知识目标细分）；进阶版和高阶版各有 1 个任务。一个任务可拆成多场，每场约 20 分钟、恰好包含 8 道题。

课程范围包含英语，但二年级具体教材起点和版次须按学校实际用书核对。人民教育出版社说明，其英语系列主要供三年级起始国家课程使用，一、二年级预备级供地方课程规划选用；因此不能仅凭“人教版”或 TapXWorld 中存在 PDF 推断学校使用人教版二年级英语。学校确认使用后才按相应版次录入，否则该册保持待核状态。语文二年级教材在 2025 年修订，旧版目录不能直接作为当前目录。练习题、提示、解释和配图均为原创，不将教材 PDF、封面、扫描页、插图或大段原文复制到仓库或网站。

本阶段实现范围：

- 二年级上学期和下学期的全部语文、数学、英语课程条目。
- 每个可玩的课程条目（正式单元、复习和综合实践）都可选择基础版、进阶版、高阶版；基础版至少 2 个任务，进阶版和高阶版各 1 个任务。任务按知识目标组织，可包含一个或多个恰好 8 题的场次。
- 现有课程目录、游戏、鼓励反馈、主题、学习起点、学习进度和成就功能的回归覆盖。
- 保留十二星区宇宙探索成就主题。星区覆盖一年级至六年级上下学期；实际学习节点和头衔进度只根据已录入并核实的课程生成。当前仅二年级两学期具备可玩的全量课程，其他年级仍标为规划中，不虚构教材单元。

## 教材版次与课程清单

TapXWorld 仓库会更新不同步，其维护者也提示仓库内容不保证为最新。人民教育出版社的公开资料说明，二年级统编语文在 2025 年有修订，二年级课文和语文要素有调整；数学新教材也有新版编排。因此不能直接把仓库中的旧 PDF 标成学校当前版次。

课程录入前需要核对学校当前使用的教材封面、版权页、目录和出版社资料。每册教材在内容元数据中记录书名、版次或印次、ISBN（教材有提供时）、出版社来源链接、核对日期、来源仓库提交号和核实状态。当前学校书目尚未核实的课程不得开放游玩、不得计入成就；现有 MVP 内容仅作为待核的旧数据迁移，不代表已经对齐学校当前教材。发生差异时使用学校当前版次修正课程条目；不混合不同版次的课文、单元或答案。最终单元数量以核对后的教材目录为准，并在实施计划的课程清单中逐册列明。

当前已核对的 TapXWorld 快照只能作为盘点初稿：

| 学科 | 上学期快照 | 下学期快照 | 版次注意事项 |
| --- | --- | --- | --- |
| 语文（人教统编） | 8 个单元 | 8 个单元 | 2025 年有修订；课文和教学要素须按校用版复核 |
| 数学（人教版） | 9 个编号目录条目，另有综合实践活动 | 10 个编号目录条目，另有综合实践活动 | 快照为旧版材料；当前校用版目录须重新核对 |
| 英语（人教版，一年级起点） | 6 个语言单元及 2 个复习板块 | 6 个语言单元及 2 个复习板块 | 快照为旧版材料；以学校实际使用的起点教材和版次复核 |

复习板块和综合实践内容不得遗漏：作为带有 review 或 integrated-practice 类型标记的课程条目或场次呈现。界面和成就统计须区分正式编号单元与复习/实践条目，避免把课程条目数量误报为教材正式单元数。目录审核表需记录每个教材目录条目的映射位置和状态，所有正式单元及复习、实践内容都必须可进入、可完成。

所有可玩的课程条目都提供三个难度。成就统计用校用教材目录编号决定 achievementEligible：正式编号单元（教材将总复习编为编号单元时也包括在内）计入正式单元数量；未编号的英语复习板块和综合实践仍可完成、单独显示进度，但不增加正式单元头衔计数。

### 课程数据层级

课程目录路径为：

年级 → 学期 → 学科 → 单元 → 难度 → 任务 → 场次 → 题目

数据文件示例：

- src/content/grade-2/term-1/chinese/unit-01/
- src/content/grade-2/term-2/math/unit-01/
- src/content/grade-2/term-1/english/unit-01/

每个单元入口引用完整层级键，课程 ID、任务 ID 和场次 ID 全局唯一。难度标识固定为 basic、advanced、high；用户可自由选择，不要求先完成基础版才能进入其他难度。

内容模型需表达：

- 学科包含 chinese、math、english。
- 课程目录条目标注 unit、review 或 integrated-practice 类型及 active/comingSoon 状态；校用版次未核实的条目必须为 comingSoon。
- 每个可玩的课程条目包含三个难度版本；基础版包含至少 2 个按知识目标划分的小任务，进阶版和高阶版各包含 1 个综合任务。每个任务包含一个或多个场次，另标注学习目标和建议完成顺序。条目标注教材目录类型和是否计入正式单元成就。
- 每场 durationMinutes 建议为 20，且活动题数量严格为 8。题量较多时增加场次；不得为满足固定任务数而把不相关知识点拼在一起。
- 每道题具有题型、题干、提示、解释和答案定义；继续支持单选、配对、排序、分类、测量和运算，按课程知识点添加必要题型。
- 教材来源元数据只用于审计课程对齐，不嵌入受版权保护的原文或插图。

## 学习流程与鼓励反馈

1. 首页显示当前学习位置和用户自己的课程进度；课程目录可切换二年级上下学期及语文、数学、英语。
2. 单元页展示基础、进阶、高阶三个入口和本机进度；基础版展开多个小任务，进阶版和高阶版各展示一个任务。任务卡片显示目标、建议时长、场次数和完成进度。
3. 每场一次呈现一道题；答对和答错时都从对应的鼓励文案池随机选择反馈，再显示必要讲解。每个反馈池包含多条贴合状态的文案；连续反馈尽量不重复，随机选择逻辑支持注入随机源以便测试。答错反馈先鼓励再给线索，允许查看提示并重试，不扣分、不惩罚，也不把错误说成答对。
4. 每场恰好完成 8 题后显示总结和继续学习入口；可自由选择其他场次或难度。
5. 基础版的全部任务及其全部场次完成后，该单元计入完成状态、首页进度和对应星区节点。只完成部分基础任务时显示单元内任务进度，不提前点亮正式单元。进阶版和高阶版的单个任务可独立记录一个或多个场次的完成进度，但不是完成正式单元或晋级头衔的前置条件。
6. 鼓励语覆盖欢迎、尝试、答对、答错、查看提示、重试、完成和连续学习等状态；按状态分别随机轮换，不使用焦虑、责备或排名式措辞。

## 配对题行为修复

现有配对题左右两栏按同一个 pairs 数组顺序渲染，导致答案和问题逐行对齐，容易直接猜中。

新行为要求：

- 左栏维持题目顺序，右栏在每次新尝试开始时单独打散。
- 同一尝试中的答案顺序保持稳定；状态更新或组件重渲染不得重新洗牌。
- 重新开始或重试时重新打散；当有两个或更多配对时，右栏不得与左栏保持完全相同的对应顺序。
- 作答和判分仍根据稳定的 pair ID，不根据数组下标或页面位置。
- 测试通过注入确定性随机源验证洗牌和重试；E2E 验证界面没有按行暴露答案且所有正确配对仍能完成。

## 学习进度与宇宙探索成就

- 复用已批准的十二星区主题和宇宙探索头衔。星区标题覆盖一年级至六年级各学期；二年级两学期展示当前实际核对出的学科、正式单元和进度，未来年级只显示规划状态。
- 每个星区可按学科分组显示单元节点；完成节点使用勾选和高亮，未完成节点置灰，并同时提供文字状态，不仅依赖颜色。
- 首页只展示当前用户的摘要进度；点击进入成就详情查看十二星区、课程节点、已完成数、总数和头衔进度。
- 头衔按已完成正式单元数升级。正式单元只由该单元基础版全部任务的全部场次完成点亮；进阶版、高阶版的完成度单独展示，不重复增加单元数。
- 设置中的学习起点可选择实际已登记课程位置。设为某位置后，之前的正式课程单元显示为已完成，目标单元及之后依实际进度显示。更改起点将替换该位置之后的本机进度，界面在应用前明确说明影响。
- 从现有进度格式迁移时保留有效学习起点；旧版少题场次不得自动标记新版 8 题场次完成。旧完成记录仅在可证明内容版本相同的情况下映射，否则保留为旧版记录并提示其不会替代新课程完成状态。

## 测试策略与覆盖率

测试覆盖所有已上线功能，并分为 Vitest 单元/组件测试和 Playwright E2E。测试使用独立浏览器上下文和专用本地端口，不复用用户当前浏览器、端口或 localStorage。覆盖率报告由 Vitest 的 V8 provider 生成；Playwright E2E 作为端到端行为验收，不混入单元覆盖率分母。

建议采用 Vitest、@vitest/coverage-v8、React Testing Library、jsdom 和 Playwright。版本安装时核对与仓库 Node.js、Vite、React 的兼容性并锁定依赖。Vitest 官方文档支持 V8 coverage、显式纳入未被测试导入的源码文件以及覆盖率阈值；Playwright 官方文档支持用 webServer 启动独立本地站点。

### 覆盖率门槛

覆盖率以全部应用源码为分母，包括 src 下的 TypeScript/TSX 文件；不把测试本身、类型声明、CSS、图片、构建产物或第三方依赖计入。配置必须显式 include 全部应用源码，避免只统计恰好被测试导入的文件。

- 全局 lines、statements、functions、branches 四项均不低于 60%。
- 核心学习逻辑对应的模块 lines、statements、functions、branches 四项均为 100%。
- 覆盖率阈值在 Vitest 配置中强制执行；低于门槛时命令和 CI 均失败。
- 不用排除文件、忽略分支或快照替代真实断言来抬高覆盖率。确需排除不可执行代码时记录理由并审查。
- 测试通过只证明相应自动化断言所覆盖的行为；教材内容正确性还需按实际校用版逐单元审核。

核心模块以纯函数和明确边界承载业务规则，目标 100% 的模块清单：

- src/app/router.ts：路径生成和解析、未知路径、筹备中课程、嵌套刷新。
- src/content/curriculum.ts 与新增课程校验模块：目录完整性、唯一 ID、有效引用、每个可玩课程条目的三个难度、基础版至少 2 个任务、进阶/高阶各 1 个任务及每场 8 题。
- 新增配对洗牌、答案判定、鼓励反馈选择和场次状态机模块：题型答案判定、错误/提示/重试、状态对应的随机反馈、连续点击保护、完成边界。
- src/storage/progress.ts：空状态、读写、损坏数据、旧版迁移、不可用存储、重复完成和学习起点替换。
- src/achievements/position.ts、src/achievements/progress.ts、src/achievements/exploration.ts：十二星区映射、学习位置、已完成数、头衔阈值和基础/进阶/高阶的计数边界。
- 新增主题偏好纯逻辑模块：默认跟随系统、手动覆盖、恢复系统设置和本机持久化。
- 新增鼓励反馈纯逻辑模块：按答对/答错等状态选取对应文案，随机源可注入以测试抽样边界和连续文案变化。

若现有组件把关键逻辑和展示耦合，实施时将业务规则提取到可单测模块；React 组件的交互状态通过组件测试覆盖。

### 单元和组件测试矩阵

- 课程数据：遍历全部年级二学期三学科课程；检查课程目录与数据条目一一对应、每个可玩条目具备三个难度、基础版至少 2 个任务且进阶/高阶各 1 个任务、每个任务至少包含一个场次、所有场次正好 8 题、课程/任务/场次 ID 唯一、题目答案引用有效、排序/分类/配对结构正确，并核对正式单元计数标记。
- 路由和目录：主页、上下学期、学科切换、单元、难度、场次、筹备中和未知路径。
- 题型：所有题型的正确/错误答案、提示、重试、锁定状态、键盘操作和正确反馈；配对验证两栏顺序、ID 对应、重试洗牌和渲染稳定性。
- 学习进度：最后一题答对才完成场次；重复点击不重复奖励；刷新保留进度；损坏或不可访问的 localStorage 不导致崩溃；新旧 schema 不产生虚假完成。
- 成就：十二星区数量和课程映射、正式单元基础版全部任务完成边界、复习/实践条目的展示规则、头衔升级边界及学习起点之前的完成计算。
- 设置和主题：默认跟随系统、浅/深色覆盖与持久化、切换学习起点后进度替换和确认文案。
- 鼓励状态、课程头像和各题型反馈：检查答对/答错只选择对应文案池、随机选择有变化、连续反馈不重复及无障碍名称。

### E2E 测试矩阵

Playwright 在隔离浏览器上下文运行 Chromium 桌面与窄屏配置，并在测试前清理本测试上下文的进度和偏好。浏览器服务器使用固定专用回环地址，reuseExistingServer 关闭，避免连接用户已有的 4173/5173 等服务。

- 数据驱动遍历所有二年级学期、学科和可玩课程条目：目录卡片、单元页、基础版多个任务、进阶版/高阶版各一个任务、课程状态和场次均可见，直接打开深层链接并刷新成功。
- 六个学期×学科入口（2 学期 × 3 学科）均能进入课程；三个学科和两学期的代表场次均能开始。
- 基础版至少完成两个不同任务的流程，进阶版和高阶版分别完成其单个任务的流程；每个任务的场次按 8 题规则显示进度并可完成，验证总结和回到单元。
- 控制随机源覆盖答对与答错反馈；答对只出现正向文案，答错只出现鼓励和线索类文案，连续触发时文案可以变化且不惩罚孩子。
- 为每种题型至少执行一个真实页面流程，包括错误、提示、重试和正确完成；配对流程还要证明答案不再与问题同序且 ID 判分正确。
- 完成基础版所有任务后首页进度、单元打勾、星区高亮和头衔更新；只完成部分基础任务或只完成进阶/高阶不得提前点亮正式单元。
- 设置弹窗可切换浅色、深色、跟随系统；模拟系统明暗偏好并刷新后验证默认/恢复跟随行为。
- 修改学习起点后按确认文案替换本地进度；刷新后成就和课程目录状态一致。
- 使用键盘完成核心答题操作，检查窄屏无横向溢出，减少动态效果偏好不会妨碍操作。
- 未知 URL 和已登记但未开放的课程分别显示未找到和筹备中状态。

Vitest 与 Playwright 测试都必须在 PR 自动检查中运行。CI 使用项目 Node.js 版本，执行干净安装、生产构建、单元/组件测试和覆盖率阈值检查、Playwright E2E；失败时保留可审阅的测试报告。具体 workflow 复用仓库既有 CI；若仓库尚无 CI，则新增最小 GitHub Actions 工作流。

## 部署、隐私与许可约束

- 继续使用 React、Vite、animal-island-ui 和静态 Cloudflare Pages 部署；构建输出为 dist，不新增后端、账号或云端学习档案。
- 进度、学习起点、主题偏好只保存在当前设备；E2E 测试不读取或覆盖用户现有数据。
- 保留已批准的 PolyForm Noncommercial License 1.0.0、第三方依赖声明、原创头像边界及教材内容不再分发规则。
- Cloudflare Pages 部署行为须以真实 Pages 构建验证；本地 Vite 构建或 E2E 成功不等于线上部署成功。

## 验收标准

1. 按学校当前实际使用的人教版教材，二年级上下学期语文、数学和英语全部正式单元、复习和实践内容均已登记并可玩；每册版次和目录映射有记录。
2. 每个可玩课程条目（正式单元、复习和实践）都有基础、进阶、高阶版本；基础版至少拆分为 2 个知识目标明确的小任务，进阶版和高阶版各有 1 个任务。正式单元计数与教材正式编号一致；每个任务可拆成多场，各场恰好 8 题、约 20 分钟。
3. 配对题右侧答案每次尝试独立打散、单次尝试稳定、重试重新洗牌，判分根据配对 ID。
4. 正式单元只在基础版所有任务的全部场次完成后计入首页、成就和头衔；部分任务完成只显示单元内进度；进阶/高阶分别记录。
5. 每次答对或答错都从对应状态的多条鼓励反馈中随机选择；连续反馈尽量不重复，答错反馈不羞辱、不惩罚，并保留清楚的讲解和重试方式。
6. 十二星区展示当前用户真实进度；后续未录入年级不伪造教材节点。学习位置设置、主题设置和本机进度可持久化。
7. 所有功能具备相应单元/组件测试和端到端测试；全局 lines、statements、functions、branches 均至少 60%，上述核心模块四项均 100%，阈值由工具和 CI 强制。
8. Playwright 覆盖目录、所有学期学科单元导航、基础版多任务、进阶/高阶单任务、题型操作、完整 8 题、随机反馈、进度刷新、成就、设置、主题、键盘和窄屏关键路径。
9. 所有过程文档为中文；从旧设计/实施计划中移除“不新增自动化测试”的过时约定，并在 AGENTS.md 增加测试命令、覆盖率标准和 E2E 启动说明。
10. npm run build、单元/组件测试、覆盖率门槛、Playwright E2E、git diff --check 均通过；没有实际 Cloudflare 部署时明确标注未验证线上部署。
