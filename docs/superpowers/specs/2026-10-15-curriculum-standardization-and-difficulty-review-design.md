# 课程目录规范与难度任务扩充设计

> 状态：设计方案已获用户批准；等待用户审阅本规格。实施尚未开始。

## 目标与范围

统一星岛学园课程文件、README 和课程编写规则，并扩充与复核二年级上下学期语文、数学、英语的全部可玩内容。范围是课程注册表中的 53 个可玩条目，包括正式单元、英语复习站和数学综合实践；不包含规划中的其他年级或未开放条目。

本工作保留当前已采用的 TapXWorld 固定教材快照、版次说明、原创内容和 PolyForm Noncommercial License 1.0.0，不下载或托管教材文件，不改变学习进度与成就计算规则。

## 现状与目录决定

当前 53 个课程入口已经符合年级、学期、学科、条目逐层存放的结构：

```text
src/content/grade-{年级}/term-{学期}/{chinese|math|english}/{条目}/index.ts
```

正式单元使用 `unit-NN`，复习使用 `review-NN`，综合实践使用 `integrated-practice-NN`。本次不搬动已有目录；以保留路径、补全约定、建立一致性校验的方式标准化，避免大量纯移动改动遮蔽课程审校结果。

单元入口、完整课程 ID 和注册表映射继续使用现有结构。新增课程文件必须放在其对应年级、学期和学科目录内；同一学期学科共用的编写器和题目辅助函数留在该学科目录下，不复制到单元目录。

## 难度、任务与题目数量

所有 53 个可玩条目都必须有三档难度。基础版继续保留至少 2 个任务；进阶版和高阶版各必须恰好有 2 个任务。每个任务包含一个 20 分钟、恰好 8 道题的场次。每个进阶、高阶任务都需要独立的标题、目标、情境和题目；不能通过复制同题、换数字或换角色名称来凑数。按当前每个条目进阶、高阶各 1 个任务计算，本次需要新增 106 个任务、848 道题。

任务和题目继续以完整课程路径生成稳定 ID，并按各难度内的 `task-01`、`task-02` 排序。进阶、高阶新任务复用现有课程路由、判题和进度能力；不能改变正式单元仅由基础版完成情况点亮的成就规则。

### 难度边界

| 难度 | 教学目标 | 可接受的思维要求 | 禁止情况 |
| --- | --- | --- | --- |
| 基础 | 掌握一个明确知识点 | 直接辨认、复述、一步计算或有提示的练习 | 混入未教知识点；把易错题当陷阱 |
| 进阶 | 将已学知识用于新但熟悉的情境 | 组合两个相关知识点，或在一步迁移中选择恰当方法 | 仅增加题量/数字，冒充迁移；依赖高年级先修知识 |
| 高阶 | 在已学范围内独立规划和说明策略 | 跨两个或更多相关知识点进行多步推理、比较方案或解释判断 | 超年级运算、冷僻词汇、歧义答案、竞速压力或故意误导 |

同一条目内两项进阶任务应覆盖不同目标或迁移情境；两项高阶任务应要求不同的策略组合。高阶比进阶增加的是推理与策略选择，而不是未经学习的知识。每题须服务任务目标和课程 `sourceTopics`，且语言及信息量适合二年级学生。

## 目录、命名与 README 规范

新增中文《课程目录与内容编写规范》，作为课程作者的单一入口，规定：

- 规范目录模式、学科 ID、条目类别名称、二位序号、`index.ts` 入口和同学科共享编写器位置。
- 单元、任务、场次和题目的稳定 ID 生成规则；禁止重复 ID、用临时序号绕开目录顺序或把复习/综合实践伪装成正式单元。
- 课程来源字段、原创内容边界、难度分级和完整题目审校要求。
- 新增课程时必须同步目录注册表、课程入口和数据校验，并执行指定检查命令。

课程结构测试检查 53 个可玩目录与注册表一一对应、入口文件存在、路径命名合法且无无效课程目录。物理目录保持当前简单结构，不将每道题拆成独立文件。

README 使用稳定章节顺序：项目介绍；快速开始；课程范围与难度；课程目录规范；内容来源与逐题审校；测试、覆盖率与 E2E；Cloudflare Pages 部署；品牌素材、隐私和许可。课程统计区分正式单元、复习和综合实践，并准确声明三档任务数。项目包元数据名称和文档统一为 `starry-island`，锁文件与之同步。

原全课程规格与已完成计划继续作为先前交付的历史记录；在其开头增加中文说明，指出新规格覆盖当前任务数量和内容审校规则，避免历史检查项被误读为当前要求。

## 逐题审校要求

本次审校覆盖 53 个条目中基础、现有进阶/高阶及新增任务的每一道题，不仅审新题。审校按“完整课程数据生成后的实际题目清单”进行，并留下中文记录：每个条目记录题量及正确性、清晰度、年龄适配、教材主题对齐和难度归属的完成状态；发现并修复的问题记录题目 ID 与改动原因。所有条目的已审题数必须与数据中的题目总数相等，未审完不得标记完成。

每题检查：

1. 答案唯一且答案键准确；选项没有第二个同样合理的正确答案；配对、排序和分类数据均有完整、无冲突的答案定义。
2. 题干、提示和讲解一致；提示提供线索而不与题目冲突；解释能说明答案，不依赖隐藏条件。
3. 内容落在对应 TapXWorld 册次的已登记知识点范围内，保持原创表达，不照录受版权保护的课文或题目。
4. 二年级学生能理解题目中的语言、情境、单位和必要背景；句子不含不必要的歧义或超龄负担。
5. 题目难度符合所属任务目标；同一 task 的八题围绕目标递进，不能以难度命名替代实际设计。

学科专项检查：数学逐式复算，核对单位、进退位、运算顺序及情境条件，并用自动测试发现表达式与答案数值不一致；英语检查拼写、大小写、词义、句法和题目目标；语文检查字词、语言知识、题意及叙述是否准确、自然。自动校验用于筛查结构、答案引用和可计算答案，不能代替逐题人工语义审校。

## 代码与兼容性要求

- 将中文、数学、英语三个共享课程构建器的进阶/高阶 spec 从单个任务改为恰好两个任务的固定 tuple，并按数组顺序构造 `task-01` 和 `task-02`。
- 课程校验器拒绝可玩条目中进阶或高阶任务少于/多于 2 个；保留基础至少 2 个、每场恰好 8 题、ID 唯一和现有教材元数据校验。
- 更新 53 份课程入口、课程清单测试、校验器测试、目录一致性测试及 E2E；访问第二个进阶/高阶任务的路由、刷新、进度存储和详情页均须验证。
- 对数学算式的答案数值增加安全的可计算校验；不使用 `eval` 执行课程字符串。无法由自动程序证明的词义、语义配对和年龄适配，保留在人工审校记录中。
- 保持现有全局覆盖率至少 60%、核心逻辑四项覆盖率 100% 的门槛，并保持 Cloudflare Pages 静态部署。

## 验收标准

1. 53 个已注册可玩条目全部符合目录规范，文档和 `package.json`/锁文件使用统一项目名。
2. 每个条目基础任务至少 2 个，进阶和高阶各恰好 2 个；每个任务的场次为 20 分钟、恰好 8 道题；共新增 106 个高阶轨道任务和 848 道题。
3. 所有旧题与新题逐题完成审校，审校台账数量和课程数据题量一致；发现的问题已修复，或有明确的待处理原因且课程不得标记完成。
4. 数学可计算答案自动校验、所有题型答案结构校验、目录和课程注册表一致性校验通过。
5. 数据驱动 E2E 可以打开、刷新并完成第二个进阶和高阶任务；跨学期、学科和复习/综合实践条目不缺失。
6. `npm run test:unit`、`npm run test:coverage`、`npm run test:e2e`、`npm run build` 与 `git diff --check` 通过；无 UI 改动时不重复扩大视觉验收范围。

## 实施方式

规格经用户审阅后，再写逐任务实施计划。计划按 Native 顺序实施，先做规范和数据模型，再分学期/学科扩写课程与逐题审校，最后统一运行测试和审查。实施阶段不得跳过用户指定的 100% 题目审校；每一批课程需先有题量与审校记录，再进入下一批。
